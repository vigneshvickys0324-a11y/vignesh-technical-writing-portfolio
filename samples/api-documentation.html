A Beginner's Guide to REST APIs

Learn how applications communicate through HTTP requests and responses.

Audience: Beginner developers and technical learners

Overview

An application programming interface (API) defines how software systems communicate. A REST-style API commonly exposes resources through URLs and uses HTTP methods to describe operations on those resources.

For example, a book-management application might let a client retrieve a book, create a new record, update information, or request deletion through an API.

Key API concepts

  • Endpoint: The URL used to access a resource or operation.
  • HTTP method: Indicates the intended action.
  • Headers: Provide metadata such as content type and authorization information.
  • Request body: Contains data submitted with a request when required.
  • Response: Contains the result returned by the server.
  • Status code: Indicates the general outcome of the request.

Common HTTP methods

  • GET — retrieve a resource.
  • POST — submit data, often to create a resource.
  • PUT — replace a resource representation.
  • PATCH — partially update a resource.
  • DELETE — request deletion of a resource.

Example: Retrieve a book

The following illustrative request retrieves a book with ID 42. The example domain is reserved for documentation and is not a live API.

GET https://api.example.com/books/42
Accept: application/json

A successful response might return status code 200 OK and a JSON object such as:

{
  "id": 42,
  "title": "A Short Guide to APIs",
  "available": true
}

The client can read the response fields and display the book's details in its interface.

Common HTTP status codes

  • 200 OK — the request succeeded.
  • 201 Created — a resource was created successfully.
  • 400 Bad Request — the request contains invalid input or is malformed.
  • 401 Unauthorized — valid authentication credentials are missing or not accepted.
  • 403 Forbidden — the server refuses the requested access.
  • 404 Not Found — the requested resource could not be found.
  • 500 Internal Server Error — the server encountered an unexpected condition.

Authentication and security

Some APIs require authentication before a client can access protected resources. Depending on the API, this may involve an access token or another supported credential mechanism.

Follow the API provider's authentication instructions, use HTTPS, and avoid exposing secrets in source code, public repositories, or logs. Access permissions should be limited to what the application needs.

API documentation best practices

  1. Explain the purpose of each endpoint.
  2. Document required parameters, headers, and request bodies.
  3. Provide valid request and response examples.
  4. Describe expected status codes and common errors.
  5. Document authentication requirements and relevant security considerations.
  6. Keep examples aligned with the actual API contract.

Conclusion

REST APIs provide a common approach to communication between software systems. Understanding endpoints, HTTP methods, request formats, and status codes gives developers a useful foundation for integrating services and troubleshooting problems.
